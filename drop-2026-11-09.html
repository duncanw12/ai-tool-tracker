devvmFree, open-source (MIT) command-line tool that gives each project folder its own virtual machine, built for running coding agents (Claude Code, Codex, opencode and pi) away from your real files and keys. Run devvm in a project and it detects the toolchains your files call for (a package.json gets node), builds the VM on Lima, mounts only that project folder at the same path as on your machine and opens a shell in it. New VMs start on an allowlist network tier so they reach only the hosts you approve, and your secrets, such as your GitHub and Claude Code tokens, stay on your machine. Built-in docker, nix and desktop layers; releases are signed with a minisign key. Needs macOS 13 or newer, or Linux, on arm64 or x86_64 (tested on Apple silicon Macs and on Linux, not yet on Intel Macs). About 430 GitHub stars; v0.1.0 shipped Nov 6, 2026 (v0.1.1 is still a release candidate) and its Show HN reached about 190 points. Very new, so treat it as early software.

Why these two

  • devvm is for anyone who lets a coding agent run commands. Run devvm in a project folder and it makes a VM for that project (on Lima), mounts only that folder, and opens a shell inside it, where Claude Code, Codex, opencode or pi can work without seeing the rest of your computer. New VMs start on an allowlist network tier, and your GitHub and Claude Code tokens stay on your machine. It is free (MIT), signs its releases and needs macOS 13+ or Linux. About 430 GitHub stars, v0.1.0 on Nov 6 and a Show HN that reached about 190 points. It is very new (v0.1.1 is still a release candidate and Intel Macs are untested), so treat it as early software. It sits between a plain container and a full sandbox like Strands Box, and it pairs well with Stroq if you want an audit of what an agent already did on your real machine.
  • sandbox-mcp brings the same throwaway idea to Windows. Built on Windows Sandbox (Windows Pro or Enterprise), it boots a clean Windows 11 machine, deploys an app or installer, drives the desktop with UI Automation, saves screenshots, recordings and crash evidence, then deletes the machine. Use the sbx command line on its own, or add the optional MCP server so an agent can run the same loop. Guest networking can be off, firewalled or on. It is free (MIT), made by Scott Hanselman, with about 355 GitHub stars; v1.0.0 shipped Nov 6 and v1.2.0 on Nov 7. It runs one machine at a time and the author is clear that not every Windows app works in Windows Sandbox. For a help desk or home-lab learner it is a safe way to try an installer or practice a clean-PC test before touching a real computer.

Listing updates

Checked on Nov 9, 2026 against official pages and release notes.

  • Stroq: v0.31.0 (Nov 8) adds stroq inspect, which reads a folder someone sent you for code that runs when fetched or decoded, hidden code, scripts that fetch into a shell and config files a tool runs by itself; these are places to read, not verdicts, and a clean result does not make a folder safe. The hook now asks the first time an agent runs code in such a folder. v0.31.1 (Nov 9) fixes stroq sent missing an environment dump inside a Python f-string URL. About 225 GitHub stars.
  • Claude Code: v2.1.319 (Nov 6) adds a permissions.denyInsteadOfPrompting setting that denies a tool call that would wait on a permission prompt and lets the turn continue, and moves MCP tasks to the background right away. v2.1.317 (Nov 3) asks before a web or shell tool call sends your account email address to the network.
  • Wazuh: 4.14.10 (Nov 9) is a maintenance release for 4.x with security fixes, including path traversal in the agent diff-folder cleanup and a root-level OS command injection in the rootcheck promiscuous-interface check. Wazuh 5.0 is still a release candidate.
  • Grim Prompter: v1.0.0 (Nov 8) is the first stable release of the threat-modeling prompt library, with privacy workflows, optional LINDDUN methods and GDPR and CCPA/CPRA profiles. The release notes call their checks bounded and not a legal compliance validation. About 400 GitHub stars.
